# v0.4.4 — Production Backup

**Status:** Planned after the repository is public. The release design gate must
be completed before implementation.

## Goal

Recover production Household records after accidental deletion or database loss
while keeping Hearth on Supabase Free.

## Proposed flow

1. A scheduled GitHub Actions workflow in a separate private repository connects
   to production with a database credential held only as a repository secret.
2. It exports the application and Auth schemas, encrypts the dump with `age`,
   and stores the encrypted file as a private workflow artifact.
3. GitHub reports failed workflows; configure a retention period that fits the
   repository's available artifact storage.
4. Restore a selected dump into an isolated non-production database and verify
   schema, Auth Users, Memberships, and Household data before relying on it.

## Boundaries

- The database dump does not include Supabase Storage objects. Decide separately
  whether private Avatar objects need their own backup.
- Keep the `age` decryption key outside GitHub and outside the backup repository.
- Do not store production dumps in Hearth's public repository.
- A backup is not considered proven until a restore has been completed.

## Decisions to resolve before implementation

- Finalize the production connection method and least-privilege access. Supabase
  may not permit a role with the required access to `auth`; if so, document why
  the project database password is necessary and restrict its use to the job.
- Set artifact retention from measured dump size and available GitHub Free
  storage; 30 days is the target, not an assumed allowance.
- Choose failure notification and restore cadence.
- Decide whether and how to back up Avatar objects.

## Acceptance criteria

- Scheduled encrypted exports complete without putting plaintext dumps or the
  decryption key in GitHub logs or repository files.
- Failed or missed exports produce a visible notification.
- A selected encrypted dump decrypts and restores into an isolated database.
- The restore contains expected schema, Auth Users, Memberships, and Household
  records; the production database is never the restore target.
- Retention and storage use are measured and remain within the chosen free-tier
  limits.
