# v0.4.4 — Production Backup

**Status:** Shipped 2026-10-21.

## Design

A nightly GitHub Actions job in the private `EthanWellsSr/Hearth-Backup`
repository runs `pg_dump --data-only` on production's `public` and `auth` schemas
and commits the result as `backup.sql`. Git history keeps every night's copy.

- **Schedule:** 04:50 UTC (11:50 PM Central daylight time, 10:50 PM in winter),
  plus a manual Run workflow button.
- **Connection:** the `DATABASE_URL` Actions secret, using the `postgres` login
  through the session pooler. Supabase does not let a custom read-only login read
  the `auth` schema.
- **No encryption:** the repository is private, and Supabase stores passwords as
  one-way hashes. The file holds email addresses and Household data.
- **Restore:** apply Hearth's migrations to an empty database, then load
  `backup.sql`. The tables come from migrations; the file holds data only.
- **Restore test:** the backup repository's manual Restore test workflow does
  this on a throwaway Supabase on the GitHub runner and checks the row counts
  and links. It passed on 2026-10-21.

## Not covered

- Avatar images in Supabase Storage.
